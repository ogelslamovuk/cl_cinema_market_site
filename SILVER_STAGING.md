# Silver Screen: файловый staging

Staging не подключается к базе Silver Screen и не выполняет SQL. Он принимает
только CSV, который заказчик получил утверждённым способом.

```powershell
python market.py silver-stage --file C:\path\approved_export.csv
python market.py silver-stats
```

## Поведение

- файл идентифицируется по SHA-256 и повторно не импортируется;
- grain проверяется по уникальному `session_id` внутри batch;
- обязательные поля сверяются с черновиком SQL;
- headerless-экспорт DataGrip принимается только в точном 35-колоночном порядке
  согласованного PoC query;
- исходная строка хранится сжатой и защищена row hash;
- количества и суммы сохраняются точным текстом без float-преобразования;
- статус нового batch — `staged_unmapped`;
- staged-строки не участвуют в доле рынка.

## Явная активация метрик

После проверки SQL и контрольных итогов конкретный batch активируется отдельной
командой. До решения заказчика её выполнять нельзя:

```powershell
python market.py silver-approve `
  --batch-id <ID> `
  --ticket-column <СОГЛАСОВАННОЕ_ПОЛЕ> `
  --revenue-column <СОГЛАСОВАННОЕ_ПОЛЕ> `
  --inactive-policy <include|exclude> `
  --approved-by <КТО_СОГЛАСОВАЛ> `
  --approval-note <КОНТРОЛЬНАЯ_СВЕРКА> `
  --confirm SILVER_METRICS_REVIEWED
```

Активация работает только с локально staged CSV и не подключается к Silver
Screen. Выбор полей, политика неактивных сеансов, автор и основание сохраняются
как неизменяемый audit trail. Повторное утверждение с другой логикой запрещено.
Политика `exclude` дополнительно требует заполненного и однозначно распознанного
`session_active`; пустой или неизвестный статус блокирует активацию batch.

Переход к `ready` возможен только после утверждения:

1. смысла `reports.sales.type = 1/2`;
2. знака возвратных строк;
3. поля кассы (`grossSum`, `priceSum` или иного);
4. правила отменённых/неактивных сеансов;
5. географии и вместимости.

После статуса `ready` exporter берёт последнюю утверждённую версию каждого
`session_id`, строит дневные, прокатно-недельные и фильмовые агрегаты. Доля на
dashboard пересчитывается по выбранным фильтрам и скрывается при покрытии
завершённых сеансов ByCard финальными снимками ниже 95%.

Для текущего PoC согласованы `net_ticket_quantity` и `net_gross_amount`.
`net_price_amount` не используется: возвратный `priceSum` в исходной выборке
имеет положительный знак и без отдельной нормализации не является нетто-суммой.
