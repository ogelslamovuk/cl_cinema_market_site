# Приёмка первой рабочей версии

## Что считается готовой системой

- collector непрерывно обнаруживает расписание по двум публичным источникам
  ByCard и снимает продажи относительно фактического stop-sale;
- exact API-продажи, оценки внешних интеграций и отсутствие данных не
  смешиваются;
- SQLite хранит исходные ответы, hashes, версии расписания, снимки, статусы и
  audit runs;
- JSON-витрина строится детерминированно, проходит `verify.py` и читается
  статическим dashboard;
- Silver Screen CSV не влияет на KPI до явного бизнес-согласования batch;
- после согласования доля считается по одинаковым периоду, географии, кинотеатру
  и точному названию фильма для обоих источников;
- доля скрывается, пока best-available покрытие завершённых ByCard-сеансов ниже 96%;
- PoC запускается одним Python-процессом и корректно завершается по `Ctrl+C`;
- JSON обновляется атомарно, поэтому dashboard не читает частично записанный файл.

## Когда данные можно показывать как долю рынка

Одного успешного запуска недостаточно. Для выбранного периода одновременно
нужны:

1. пригодные best-available снимки минимум 96% завершённых ByCard-сеансов;
2. отсутствие необъяснённых source anomalies;
3. утверждённый Silver Screen query и сверка одного дня по билетам и кассе;
4. статус соответствующих SS batch `ready`;
5. совпадающий календарный диапазон двух источников.

## Текущее состояние данных на 2026-08-03

Локальная БД содержит ранее обнаруженное расписание и частичные снимки, но сбор
начался после значительной части stop-sale. Поэтому этот день годится для
технической проверки интерфейса, но не для вывода о доле рынка. Dashboard
намеренно показывает отсутствие готовой доли вместо экстраполяции.

## Внешние шаги до production

- согласовать и проверить query Silver Screen в отдельной задаче;
- выбрать машину для непрерывного запуска и стартовать collector до начала
  полного прокатного дня;
- определить репозиторий и режим доступа к dashboard;
- определить допустимый режим доступа к опубликованным рыночным данным;
- после первых полных суток принять контрольный отчёт и только затем считать
  долю продуктовой метрикой.
